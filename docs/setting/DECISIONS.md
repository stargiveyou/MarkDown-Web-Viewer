# DECISIONS — 아키텍처 결정 기록 (ADR)

## ADR-001. 업로드는 웹 → 로컬 디스크 직접 저장 (FTP 미사용)
- **상태**: ✅ 확정 (D1=A)
- **결정**: 웹 업로드 API가 파일을 맥미니 로컬 `~/MarkdownDocs`에 직접 저장. FTP 서버/basic-ftp/FTPS 미사용.
- **근거**: 저장소가 로컬 디스크라 FTP 경유 불필요. 공격면·운영 부담 제거, 단순화.
- **영향**: `POST /api/upload` 신설. `FTP_*` env·의존성 전부 제거. 경로 검증 + atomic write.
- **되돌림 조건**: 외부 FTP 클라이언트 직접 업로드가 필요하면 D1=B로 전환.

## ADR-002. 저장소 통합 — 단일 로컬 디스크
- **상태**: ✅ 확정 (요구사항 3)
- **결정**: 업로드 저장·뷰어 읽기·편집 대상이 모두 동일한 로컬 디스크.
- **근거**: 올린 파일이 곧바로 GridView에 나타나야 함(요구사항 5).

## ADR-003. FTP 다운로드 API 제거
- **상태**: ✅ 확정 (D2)
- **결정**: 읽기는 로컬 직접이므로 FTP 다운로드 API 미도입.

## ADR-004. 웹 공유 = 디스코드/슬랙 Webhook (카카오 제외)
- **상태**: ✅ 확정 (D3=소셜, D4=디스코드+슬랙)
- **결정**: 공유를 `POST /api/share/notify` 서버 라우트에서 Discord Embed / Slack Block Kit Webhook으로 처리. 카카오 클라이언트 SDK는 채택하지 않음.
- **근거**: 카카오 제외로 클라이언트 SDK·도메인 등록 불필요. 공유·알림이 하나의 서버 Webhook 계층으로 통합.
- **보안**: Webhook URL은 서버 전용 env, 공유 엔드포인트 세션 인증 필수.

## ADR-005. 인증 = 단일 패스워드 세션 + ngrok Basic Auth
- **상태**: ✅ 확정
- **결정**: 1인 사용 기준 패스워드 세션(httpOnly 쿠키) + ngrok 엣지 Basic Auth 이중 관문. 전 라우트 보호.

## ADR-006. 마크다운 편집 유지 (Monaco)
- **상태**: ✅ 확정 (D5)
- **결정**: 뷰어 + @monaco-editor/react 편집(`PUT /api/file-content`, Cmd+S) 유지.
- **보안/안전**: `mtime` 충돌 경고 + atomic write.

## ADR-007. 검색 = SQLite FTS5 + trigram 토크나이저
- **상태**: ✅ 확정
- **결정**: 파일명·본문·frontmatter 태그를 SQLite FTS5 색인으로 검색. 토크나이저는 `trigram`.
- **근거**:
  - 색인 방식은 파일 수가 늘어도(수천 개+) 검색 속도가 밀리초대로 유지됨. 실시간 스캔은 규모에 비례해 느려짐.
  - trigram(3글자 단위)은 한국어 조사/부분일치에 실용적(형태소 분석기는 개인용엔 과함).
  - BM25 관련도 정렬·`snippet()` 하이라이트 등 FTS5 내장 기능 활용.
- **영향**:
  - 증분 색인 갱신: 업로드·저장 이벤트 시 해당 파일 갱신(앱 경유 100% 커버) + (선택) chokidar 감시.
  - 의존성: `better-sqlite3` 등.
- **대안(기각)**: 실시간 fs 스캔 — 수백 개 이하면 무난하나 확장성에서 불리.

## ADR-008. 업로드 완료 알림 포함
- **상태**: ✅ 확정 (D6)
- **결정**: 업로드 성공 시 디스코드/슬랙 Webhook 알림. ADR-004의 Webhook 계층 재사용.

## ADR-009. 썸네일 디스크 캐시 / ADR-010. ngrok 무료 플랜
- 썸네일: sharp + 디스크 캐시(`path+mtime+width`).
- ngrok: 무료(정적 도메인 1개 + Basic Auth). IP제한·OAuth는 유료 시 승급.
